# v1.1.7 — the editor stops "disconnecting"

Two of the bugs closed here had the same disguise. A tool that held Godot's
main thread for longer than two ping cycles looked exactly like a dead editor,
so the bridge terminated its socket mid-answer and reported "Godot
disconnected" — sending everyone, including this project's own backlog,
looking for a connection bug. It was never a connection bug.

## Fixed

**`get_project_statistics` froze the editor for two minutes.** Measured against
a 24,649-file project: 120,685 ms, against a 20-second watchdog. It opened every
file with `FileAccess` just to read its length, and called `ResourceLoader.load()`
on every `.tscn` — pulling each scene's textures and scripts into the cache — to
count nodes. It now answers from disk in the MCP server, in 2,012 ms, and works
with Godot closed. Same numbers, checked field by field against the old
implementation.

**The ping watchdog killed editors that were busy answering us.** A pending
request now suppresses the staleness check; the request's own timeout is what
gives up. An idle unresponsive editor is still terminated, and both halves are
tested.

**A slow call now says so.** Anything over 10 seconds comes back with
`_perf.elapsed_ms` and what it cost, because the editor's UI was frozen for that
whole time and nothing in the answer mentioned it.

**`get_errors` could return 0 with a panel full of errors** (#4). It looked for
the Debugger > Errors tree by searching ancestor names for "Error" and, failing
that, took whichever `Tree` came first under the debugger — the profiler's or the
monitors' would do — then cached that choice for the session. It now identifies
the tree by the `_is_error` / `_is_warning` meta Godot stamps on those rows,
which works in any editor language and any dock layout, searches every debugger
tab, and re-validates the cache. When it finds nothing it says how many debuggers
and trees it looked at, so "no errors" and "could not find the panel" stop
looking identical.

**Validation stopped leaving files in your addons folder.** One
`__mcp_snippet_1.gd` was found in a real project despite the delete that runs
right after compiling: the engine can flush a `GDScript` carrying a `res://`
path to disk later. Swept before each validation now.

## New

**`analyze_2d_layout`** — where a 2D scene's pieces actually sit. Decoration
floating above the surface under it (with the gap in px), decoration standing
over a hole in the floor, decoration whose silhouette runs into a solid so the
two read as one hovering chunk, and every floor gap with its width so a jump arc
can be checked against a number. Every one of those is a bug that cost a full
session to find by hand while building a game with these tools.

**`texture_info`** — a texture's size and content alpha bbox, in-engine. Also
flags `has_internal_gap`: a fully transparent row inside the content box means
the crop contains two disconnected pieces, which a plain bounding box cannot
detect. That exact miss shipped three broken tileset sprites.

**`find_tools`** — search all 230 tools by what you want to do, including the
ones whose toolset is off. A small default surface is deliberate (38 tools,
8,665 tokens, against 47,211 for everything) but it used to mean a capability
you did not know the name of was unreachable.

**`monitor_properties({setup_code})`** — run a snippet in the same call that
starts sampling, so triggering an event and watching it no longer costs a round
trip. Sub-second behaviour (a 0.74s jump arc, a 0.12s input buffer) was
unobservable before: it was over by the time the next call landed.

**Collision shapes can be seen.** `run_scene({debug_collisions: true})` and
`render_scene_preview({show_collision: true})` draw them, set before the first
frame rather than flipped mid-session.

**Real input during an automated run is reported.** A synthetic-input counter
tells your own `send_input` apart from a stray click landing because the editor
window had focus — which once cost a long detour on a "jump does not fire" that
was a real mouse click putting the player in `attack`.

**The scene tree renders as an MCP App** (SEP-1865) in hosts that support the
extension: a collapsible panel where clicking a node tells the model what you
are pointing at. Hosts without it get the same text answer as before.

**`diagnose_connection` checks the addon against the server version.** A server
newer than the installed addon advertises tools whose GDScript handler does not
exist, which surfaces as "Unknown tool" rather than as a stale install.

## Housekeeping

MCP SDK 1.30. Worth knowing what that is not: it still advertises protocol
2025-11-25, so the 2026-07-28 spec's core changes are not reachable from the
TypeScript SDK yet, whatever the release write-ups say.

Tests: 202 Node, 577 GDScript.

**Reinstall the addon** — this release changes GDScript. `npx godot-mcp-bridge
install`, then restart the editor. From now on `diagnose_connection` will tell
you when you forget.
